WebConfig는 WebMvcConfigurer라는 Spring 인터페이스를 구현한거임.
Spring MVC 설정을 개발자가 원하는대로 추가하거나 변경할수 있도록 여러 메서드를 제공함.
그래서 addCorsMappings라는 메서드는 이미 존재해서 @override를 사용하는거임
그중 Cors 설정부분을 원하는 방식으로 재정의함.
그래서 Corsregistery객체를 받아서 여기에 설정을 추가하는거임
registry.addMapping("/api/**") 어떤 URL 경로에 CORS 설정을 적용할지 메서드 호출한거임
api 하위에 있는 전체 경로 Cors 설정 적요한다는 뜻
.으로 메서드 이어가는 방식은 메서드 체이닝이라는 기법
addMapping()으로 호출했을떄 결과로 다른 객체를 반환함.
그 반환된 객체에서 바로 .allowedOrigins(...)을 다시 호출하는거임

allowedOrigins(frontendOrigin) 어떤 Origin에서 오는 요청을 허용할것인지를 설정

Origin은 기본적으로 프로토콜 + 호스트 + 포트로 결정됨
근데 리액트 서버랑 스프링부트 서버랑 포트번호가 다르니까 서로 다른 Origin임
그래서 브라우저의 CORS정책이 관련됨.
그래서 스프링 서버가 리액트 서버의 브라우저에서 오는 요청을 허용하겠다고 설정하는것

.allowedMethods(...)는 허용 할 HTTP Method를 지정함

OPTIONS 내가 이런 요청을 보내려고 하는데 보내도 돼?라는 Preflight Request(사전 요청)를 사용할떄 OPTIONS가 사용됨

.allowedHeaders("*") *는 모든 요청헤더를 허용한다는 뜻
